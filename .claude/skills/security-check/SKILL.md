# セキュリティチェック（AIライティングツール向け）

対象は個人・単一ユーザー向けのStreamlitアプリ（認証・DBなし、Gemini APIをラップ）。
一般的なOWASP診断をそのまま当てはめるのではなく、このアプリの実際の構成（`app.py` / `utils/gemini_client.py` / `utils/common.py` / `utils/prompts.py` / `pages/*.py`）に即したリスクを優先して確認すること。

## 進め方

1. まず下記の自動チェック（grep）を一通り実行し、該当箇所を洗い出す。
2. 該当したファイルを実際に読み、誤検知でないか・実際に悪用可能かを確認する。
3. 見つかった問題は下の「重大度の目安」に沿って分類し、`ReportFindings`ツールがあればそれで報告する。なければ重大度別の箇条書きで日本語で報告する。ファイルパス:行番号、再現条件、推奨対応を必ず添える。
4. コードは指示がない限り勝手に修正しない。ユーザーに指摘して、直すかどうかの判断を委ねる。

## チェック項目

### 1. APIキー・秘密情報の取り扱い
- `.gitignore` に `.env` と `.streamlit/secrets.toml` が含まれているか確認する。
- ハードコードされたAPIキーがないか確認する。
  ```
  grep -rn "AIza\|api_key\s*=\s*[\"']" --include=*.py .
  ```
- `utils/common.py` のAPIキー入力欄が `type="password"` になっているか確認する（平文表示になっていないか）。
- 例外を画面に出している箇所（例: `st.error(f"生成に失敗しました: {e}")` in `utils/common.py`）で、APIキーやスタックトレースなど内部情報がそのまま利用者に表示されないか確認する。
- `st.session_state["gemini_api_key"]` はセッション限りの平文保持である点は仕様どおりだが、共有PC・画面共有時に漏洩しうることをリスクとして明記する。

### 2. プロンプトインジェクション／出力の暴走
- `utils/prompts.py` の各関数は、ユーザー入力をf-stringでそのままプロンプトに埋め込んでいる（例: `blog_prompt`の`topic`、`email_reply_prompt`の`original_email`など）。ユーザー自身が唯一の入力者なので直接的な被害は限定的だが、貼り付けたテキスト（他人のメール本文・外部記事など）に指示文が混入すると、意図しない出力に誘導され得る点を指摘する。
- `generate_stream`（`utils/gemini_client.py`）は`system_instruction`を使わず全てuser側プロンプトに混在させている。指示とユーザーデータの分離がない設計であることを明記する。
- 出力をそのまま`st.download_button`でファイル化・外部共有する運用があるなら、生成物に不適切な内容が混じるリスクを一言添える。

### 3. 危険な関数呼び出し・コード実行
```
grep -rn "eval(\|exec(\|os\.system(\|subprocess\.\|pickle\.load(\|unsafe_allow_html" --include=*.py .
```
- 該当があれば個別に必要性と安全性（入力が信頼できるか）を確認する。
- 特に`unsafe_allow_html=True`はXSS的リスクになりうるため、生成AIの出力をそのままHTMLとして描画していないか確認する。

### 4. 依存パッケージ
- `requirements.txt` を確認し、`>=`のみでバージョン上限がないため、意図しないメジャーアップデート・脆弱パッケージ混入のリスクがあることを指摘する。
- 可能なら以下を実行して既知の脆弱性を確認する（`pip-audit`が未インストールなら提案に留める）。
  ```
  .venv\Scripts\python -m pip list
  .venv\Scripts\python -m pip install pip-audit
  .venv\Scripts\python -m pip_audit
  ```

### 5. Streamlit特有の設定
- `.streamlit/config.toml` が存在するか確認し、あれば`enableXsrfProtection`・`enableCORS`・`server.headless`等の設定値を確認する。存在しない場合はStreamlitのデフォルト挙動（ローカル単一ユーザー前提）でリスクがないか触れる。
- アプリを`localhost`以外（`--server.address 0.0.0.0`等）で起動する運用がないか、README・起動コマンドを確認する。認証機構が一切ないため、ローカル外に公開すると誰でもGemini APIキーを消費できてしまう点は重大リスクとして扱う。

### 6. 入力値・リソース消費
- `st.text_area`系の入力に文字数上限がなく、巨大な入力がそのままAPIに送信される（コスト増・レート制限・タイムアウトの原因になりうる）。
- ファイルアップロード機能が追加されている場合は拡張子・サイズ制限があるか確認する（現状の8ページには存在しない想定）。

### 7. 出力ファイルの取り扱い
- `show_result`の`download_button`で使われる`file_name`が固定文字列であり、ユーザー入力からパスを組み立てていないか確認する（パストラバーサル等は現状の設計では発生しない想定だが、変更が入っていれば要確認）。

## 重大度の目安
- 🔴 Critical: APIキー平文漏洩、任意コード実行、外部公開時に無認証でAPIキーが消費される設定など、実害に直結するもの
- 🟡 Warning: 個人利用の範囲では許容できるが、共有・公開時に問題になりうるもの（プロンプトインジェクション耐性のなさ、依存関係のバージョン未固定など）
- 🔵 Info: 改善余地はあるが緊急性は低いもの

## 出力
各finding には以下を含めること。
- 該当ファイル:行番号
- 何が問題か（1文）
- 具体的にどう悪用・失敗しうるか（再現条件）
- 推奨対応（このアプリの規模に見合った現実的な対応。個人用ツールに大掛かりな認証基盤などを提案しない）
